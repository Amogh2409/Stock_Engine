Read this before anything else. The technical scoring model has been measured against real prices and there is no evidence it predicts returns. Rank correlation with next-month returns is −0.0060 (t −0.29, n=86), and nothing at any horizon survives correction for the number of tests run. All four scoring blocks are independently flat at one month — and that is a 1-month claim which does not extend. At six months relative strength is the one cell in twenty that rises above its own detection floor (IC +0.0784, HAC t +3.06, corrected p 0.060). It still does not clear correction, and it is recorded rather than claimed; see No block carries it below for why.

Be precise about what that does and does not establish. The smallest effect this test could reliably detect is an IC of 0.059, and a realistic cross-sectional effect is roughly 0.02–0.05 — so the measurement is not sensitive enough to rule out a small real edge. It shows an absence of evidence, not evidence of absence.

The portfolio result is the part that does not depend on statistical power. Ranking by this score returned 19.41% a year against 23.29% for simply equal-weighting the same 100 stocks over the same months — a shortfall of −3.89 points. That is a measured underperformance, not a failure to detect.

The engine is well-built, well-tested and honestly documented. What it is not, on current evidence, is a stock picker. Everything in this guide should be read with that in view.

1. What this project is

A deterministic screening engine for Indian equities. It reads a Screener.in CSV export of company fundamentals, optionally reads a price-history CSV, scores every company out of 100, ranks them, and produces a watchlist with position sizes and stop levels — in the browser, in Python, and in a Colab notebook, all producing identical numbers.

The stated goal versus where it actually is

The goalCurrent reality
Continuous Nifty 100 analysis Runs on demand from a manual CSV upload. No automatic daily run, because there is no free fundamentals feed.
Buy / sell guidance Produces entries only. Position sizing and stops now exist; there is still no sell rule or exit discipline beyond the next month's re-rank.
Percentage allocations Done. Equal-risk sizing by volatility, with an explicit cash position.
Learn from the trading books Done as documentation, not as automation. Every scoring rule is traced to a source or explicitly marked unsourced in knowledge/rulebook.md.
Research only. The engine never places an order, never connects to a broker, and has no live trading path. Everything it produces is a research signal for a human to act on or ignore.

3. How it works

The pipeline, end to end

Screener.in CSV  ──┐
                   ├─→  parse & clean  →  dedupe  →  filter to universe
Price history CSV ─┘                                        │
                                                            ▼
                                              hard red flags?  ──yes──→  REJECTED
                                                            │no
                                                            ▼
                                         fundamental score (0-100, 5 categories)
                                         technical score   (0-100, 4 blocks)
                                                            │
                                                            ▼
                                    composite = F×(1−W) + T×W      [W = 40%]
                                                            │
                                                            ▼
                                     rank → top N → equal-risk position sizing
                                                            │
                                                            ▼
                                   watchlist + weights + stops + cash position

Two engines, one answer

The same logic exists twice — python/engine.py (5,500 lines) and src/utils/screenerEngine.ts (3,809 lines). They are not approximately equal; they are asserted bit-identical by 39 parity tests that run both engines on the same data and compare every score, every text string and every CSV byte.

This is why rounding is round1() everywhere (half-up, one decimal) and why sorting uses code-point order rather than locale order. A rounding difference is a ranking difference.

Generated files — do not edit by hand. src/utils/pythonEngineSource.ts and the Colab notebook are both built from python/engine.py by npm run build:python and npm run generate:notebook. Editing the engine without regenerating them makes check:python fail, which is exactly what it is for.

4. The scoring model

Step 1 — hard red flags (rejection, not a low score)

These mean "this row cannot be trusted as evidence", not "this company is unattractive". An expensive stock still gets scored; a company with nine of these does not.

  • Negative net worth — negative P/B or D/E is insolvency, not a bargain
  • High promoter pledge — above the configured limit
  • Negative or missing operating cash flow — non-financial companies only; a growing loan book legitimately consumes cash
  • Insufficient data — too little of the row present to score honestly
  • Non-positive sales, market cap, or impossible shareholding percentages — the row is corrupt
  • Pledge without promoter holding — internally contradictory
  • Conflicting duplicate rows — two rows disagree, so neither can be believed

Step 2 — fundamental score, 100 points

CategoryPointsMeasures
Financial quality30ROCE, ROE, margins
Growth25Sales and profit growth
Balance-sheet safety20Debt/equity, interest cover, cash flow
Valuation15P/E and P/B against the sector median, not absolute
Governance10Promoter holding and pledge

Banks and NBFCs are scored by a separate model using return on assets, NPAs, capital adequacy and CASA — because leverage and interest cover do not describe a lender. A financial company whose export lacks those columns is reported as "not scored: missing bank metrics" rather than being scored wrongly on ratios that do not apply.

Step 3 — technical score, 100 points in four blocks

BlockMaxRules
Trend40Price > 200 SMA (12), > 50 SMA (8), 50>200 cross (8), ADX>25 (4), within 15% of 52-week high (8)
Momentum30MACD histogram rising (15), RSI > 50 (15)
Relative strength20Beat the benchmark over 3m (5), 6m (10), 12m (5)
Volume10Above 20-day average (5), positive OBV pressure (5)

Volatility, overbought RSI and deep drawdowns are flags, never points. Paying for low volatility tilts toward sleepy stocks and paying for high volatility toward lottery tickets; neither is defensible, and the source treats volatility as a risk measure rather than a directional edge.

A company needs 200 sessions of price history to be scored at all. Below that the score is null, not a low number — a short listing is not a weak company.

Step 4 — the composite, and what it gates

composite = fundamental × (1 − W/100)  +  technical × (W/100)      W = 40

The pass mark (minimum_total_score = 50) gates the fundamental total. The composite decides ordering, not admission. Companies that pass but cannot be priced are ranked in a separate list, because a composite without a technical half is not on the same scale — mixing them would reward being absent from the price file.

Step 5 — position sizing

Equal risk by volatility (weight proportional to 1/volatility, normalised), scaled to a 12% portfolio volatility target, then capped per position and per sector. Stops at 2× ATR. The shortfall stays in cash and the app says why.

This is the best-sourced part of the system — real page citations, a worked table from the source, and an explicit decision rule. Note the direction of that argument: equal risk is what the book prescribes precisely because the selection underneath it is unproven. The sizing citations lend the scoring layer nothing.

5. What has been measured

Everything below is the pre-holdout window: 2015-10-30 to 2022-11-30, 86 traded rebalances, monthly, next-day-open execution, 15 bps per side, no look-ahead by construction. Data from 2023-01-01 is reserved and is not measured here.

These figures span the full period, measured before the reserved window was introduced. The backtest now stops at 2023-01-01 by default, so a plain re-run returns numbers over 2015–2022 instead and will not match the tables below. Add --no-respect-holdout to reproduce them. The reserved window is documented in knowledge/holdout.md, which states honestly that it is not pristine: it was observed once, on 13 September 2026, at composite and block level. What has not happened is the thing that actually matters — no engine parameter was changed in response to it. Used once for observation, never for fitting.

Every window is kept and the standard error corrected for their dependence (Newey–West at lag h−1), rather than discarding overlapping windows to buy independence. Overlap is not the defect; an i.i.d. standard error applied to it is. Nothing clears correction at any horizon.

None of these horizons can see a realistic effect. A plausible cross-sectional IC is roughly 0.02–0.05, and the detection floors above run 0.052 to 0.066 — strictly above the top of that range at every horizon. So every row here is an absence of evidence rather than evidence of absence, and that is true of the 1-month row too, which is the best-powered of them.

One month is still the cleanest row, for a structural reason: a 1-month forward return sampled monthly cannot overlap, so every estimator agrees there by construction. Longer horizons do overlap, which is handled by correcting the standard error rather than by discarding windows — an earlier version of this guide described that as a forced choice between inflating the t-statistic and collapsing the sample, which was wrong.

No block carries it

A near-zero total is equally consistent with four dead blocks and two that cancel out. Ranking on each subtotal alone settles it. At 1 month — the cleanest horizon, though not a well-powered one — every block sits inside its own detection floor:

BlockICt (HAC)Detectable at 80% power
Trend (40 pts)+0.0032+0.140.062
Momentum (30 pts)−0.0277−1.670.047
Relative strength (20 pts)+0.0218+1.080.057
Volume (10 pts)−0.0231−1.660.040

Four flat blocks at one month. Nothing is cancelling out at that horizon, so no reweighting of the 1-month signal recovers an edge that is not there. That conclusion belongs to the table above it and does not carry to longer horizons — an earlier version of this guide stated it without the qualifier, which generalised a 1-month result across all four.

At six months, one cell in twenty clears its floor. Relative strength, pre-holdout window, overlapping windows with Newey–West at lag 5: IC +0.0784 over n = 81, against a detection floor of 0.0725. HAC t +3.06 (SE 0.0256), bootstrap t +3.46 with a 95% interval of +0.032 to +0.120 that excludes zero. Raw p 0.0030; corrected for the 20 tests in the family, p 0.060. It is the only cell in this project above its own floor.

Why it is more likely noise than signal. It does not clear correction. Under the null, the chance that some cell out of twenty would look at least this strong is about 5.9% — which is roughly what happened. Its sibling horizons do not clear their own floors: 1 month +0.0218 against 0.0574, 3 months +0.0486 against 0.0587, 12 months +0.0672 against 0.0688. And it has not been tested on any data that was not already used to find it.

The largest correction in the study lands on this cell. Its i.i.d. t at 6 months is +4.67 and Newey–West deflates it to +3.06 — a drop of 1.61, the biggest anywhere here; the next largest is 1.08. What remains is what survived the steepest discount, not a figure that never needed one.

These twenty tests are not twenty independent looks, and that cuts against this cell rather than for it. The blocks share constituents and the horizons overlap. That does make Bonferroni conservative as a divisor — but it also means this is not a lone survivor among twenty: it is one face of a correlated cluster holding the same block at 3 months (+2.34) and 12 months (+2.77). Its consistency across horizons is not four corroborating results, it is closer to one result seen four times. No redivision admits this cell without also readmitting the ones already dismissed, because the dependence that would shrink the divisor is what makes these tests redundant rather than numerous.

Three numbers that look like findings and are not

1. The 2022-only +14.88pp. Eleven months, the one block in the whole report with no confidence interval, and the most quotable figure it produces. It is the row most likely to be lifted and the least entitled to be.
2. Any earlier +2.15% or 24.78% out-of-sample figure. Those came from a window that had already been used to revise the engine. Once out-of-sample data has been used to fix something, what comes back is overfitting — an in-sample number wearing an out-of-sample label. At 733% turnover it is negative after Indian short-term capital gains tax in any case. This is precisely why 2023 onward is now reserved and untouched.
3. The RSI flip appearing to beat equal-weighting. Scoring rsi14 < 50 instead of > 50 was tested, and its portfolio figures look better than the shipped sign's. The rank IC underneath them is approximately zero, and with no ranking signal the top-20 composition is noise — so what changed is which twenty names the noise picked, a story about twenty draws rather than about a rule. Neither sign is adopted. The figures themselves are deliberately not reproduced here: that experiment ran over the full span before the holdout and before benchmark alignment, so they are not comparable with anything above and re-running it on the pre-holdout window is the only way to get numbers that would be.

6. Status — what is done

Every commit independently verified in a clean room by a second session before pushing.

Done Core engine and parity

  • Two-engine architecture with 39 byte-identical parity tests
  • Financial-company model (banks/NBFCs scored on their own metrics, or honestly not scored)
  • Sector-relative valuation with a minimum sample size and a stated fallback chain
  • Hard red flags separated from low scores
  • Unpriced companies ranked separately rather than silently dropped

Done Technical analysis

  • 18 chart indicators: RSI, MACD, ADX/DI, ATR, Bollinger %B, OBV, ROC, drawdown, relative strength
  • Wilder smoothing, EMA seeding, population sigma — matching the textbook formulas exactly
  • Four-block scoring with per-block subtotals exposed
  • Sector-relative strength as a diagnostic (earns no points, computed after scoring so it structurally cannot reach one)
  • Price charts in the detail panel, drawn against the levels the score actually used

Done Position sizing and risk

  • Equal-risk sizing by volatility, scaled to a 12% portfolio target
  • Per-position and per-sector caps; 5% per-trade risk ceiling
  • Stops at 2× ATR, set in advance
  • Cash position shown and explained in the app, the CSV and the HTML report

Done Measurement and honesty infrastructure

  • Backtest with no look-ahead, next-day-open fills, modelled costs
  • Both overlapping and non-overlapping sampling reported side by side, with sign-flip flagging
  • Every IC printed with its sample size and its minimum detectable effect
  • Bonferroni correction across the whole family of 20 tests
  • Student's t rather than a normal approximation (at df=9 the difference decides significance)
  • The backtest's own mechanics are now inside the release gate, and proven to fail when broken
  • A reserved window from 2023-01-01, enforced in the one function every caller passes through, so a new caller inherits the protection instead of having to remember it
  • Newey-West standard errors for overlapping windows, validated against series with known overlap structure and cross-checked by an independent bootstrap
  • knowledge/rulebook.md — 961 lines tracing every rule to a source or marking it unsourced
  • Dated, hashed archive of every fundamentals export used

7. Status — what is left

Blocked on you A real Screener.in export

This is the single largest blocker in the project. data-store/fundamentals/ contains only sample_screener_export.csv, whose figures are invented. The archive has run exactly once — on that sample (verified: identical SHA-256, and none of the four bank columns present).

What to do: in Screener.in, add these four columns to the screen before exporting, then drop the CSV into data-store/fundamentals/:

  • Return on assets
  • Gross NPA %
  • Net NPA %
  • Capital adequacy ratio

What it unblocks:

  • ~23 financial companies get scored for the first time instead of "missing bank metrics"
  • The provisional pass mark of 50 gets real data to calibrate against
  • Point-in-time history starts accumulating — the only route by which the fundamental half ever becomes testable
When it arrives, split it before looking at it. Calibrate on part, and stamp the rest unexamined. Tuning the pass mark against a snapshot you have already studied spends the only clean data available and leaves the threshold exactly as unfounded as it is today, with better-looking provenance.

Your decision The technical weight

technical_weight_pct = 40 is now unearned, not merely unvalidated. Measured at six real rebalance dates, the technical score spans the full 0–100 range every month (mean span 99.3). So at W=40 the technical half can swing a composite by 39.7 points — enough to move a company across all three verdict bands (Strong ≥70, Good ≥60, Average ≥45) on its own. It is frequently the deciding term, and it is deciding on a measured null.

OptionMeaningThe honest cost
40
current		 Status quo~40 points of ordering driven by a measured null
10–20Reduce the null's influence No evidence picks any value over another — arbitrary, but smaller
0Rank on fundamentals alone Not the safe option. Concentrates 100% of ordering on the half that is untested — trades a known null for an unknown
0 + displayTechnicals shown, never ranked Keeps charts and flags as information without letting them order anything

Not computable today: how the actual watchlist composition shifts as W varies needs both halves, and the fundamentals half would be invented numbers. That calculation waits on the real export.

Not started Exits and sell discipline

The engine produces entries only. There is no exit rule, no trailing stop logic, and no sell signal beyond next month's re-rank. Against the stated goal of buy/sell guidance, this gap is structurally larger than the pass mark or any remaining scoring work. Knowing your exit in advance is basic risk management in the source material.

Deliberately unclaimed: adding exits turns a screener into a trading system, which is a product decision rather than an engineering one.

8. Known weaknesses — read before trusting any number

Structural limits of the measurement

  • Survivorship bias. Today's Nifty 100 applied to history. Companies that fell out of the index are absent and are disproportionately the bad ones. Every figure, including the benchmarks, is flattered.
  • The fundamental half has never been tested. Not "tested and found weak" — never measured at all. Today's export describes today, so applying it to 2016 would be look-ahead of the worst kind.
  • No dividends, no taxes. Costs are modelled; Indian STCG is not, and at a monthly rebalance it is the larger drag.
  • The full-span figures are frozen and cannot be repaired. Earlier versions of this guide reported 2015–2026 results. Those were measured before the benchmark window was aligned, so their equal-weight and index columns are computed on a different basis from everything published now — and they cannot be regenerated without spending the reserved window, which is a decision for the project owner rather than a presentation fix. They are not merely unearned; they are stale in a way that has no repair. Nothing in this guide relies on them.
  • The books teach single-instrument timing, not cross-sectional ranking. An indicator can time one stock well and carry no information about which of a hundred will outperform the other ninety-nine.

Rules that are convention, not evidence

Roughly half the live technical thresholds are inherited market convention with no source in any book in the repository: the 50/200 SMA pair, RSI 50, ATR 5%, the 2× ATR stop multiple, the 15% 52-week-high proximity, and the 5/10/5 relative-strength split. They are not wrong — they are unjustified, and the rulebook labels each so nobody later assumes a number was measured when it was inherited.

Three places the books actively disagree with the engine

  • RSI direction. Scoring RSI > 50 treats it as continuation. The source's own evidence shows the sign flipped around 1998 — a trend indicator before, mean- reverting since. The risk is not that the rule is unproven; it is that it may be directionally wrong in some regimes.
  • High volume near the highs. The engine pays 13 points for a configuration one source calls a buying climax and reads as bearish. The distinguishing feature is price spread, which the engine does not compute.
  • Stops may not help at all. The source is sceptical that stop-losses improve trend or mean-reversion profiles, and gives multiples of 3× and 12× ATR — neither of which is the 2× used here. The UI says so rather than letting a stop price imply a protection the books endorse.

9. Working rules — learned the hard way

Every rule below came from an actual failure in this project. They are worth following because each one has already cost time.

Before trusting a green signal, ask what it would look like if the thing were broken

If the answer is "the same", the signal carries no information. Four real instances in one day:

  • A look-ahead test compared a score to itself at fixture session 66 when scoring needs 200 — both sides were null, so assertEqual(None, None) passed for as long as the test existed, while the docstring claimed the test asserted no-look-ahead.
  • A guard returning bare None crashed on the first real run, because every test fixture gave every ticker every date. A guard for absent data is only exercised by absent data.
  • A flag was "proved" to work by printing DIFFERENT: True from nan != nan, which is true for any two NaNs.
  • A failing Python run reported exit 0, because the code came from tail at the end of a pipe rather than from Python.

A grep count is not evidence until you have read the lines

Both halves bite. A zero count means nothing unless the pattern is shown to match text known to exist — four false zeroes here came from shell glob mangling. And a non-zero count says nothing about what matched: four occurrences of __dirname were assumed to be four comments; three were, and the fourth was live code that shipped under a commit message claiming it was gone.

Verify against the whole of a thing, not its first screen

Three rulebook claims were built on the seven files at the top level of the books folder while 128 more sat in a subdirectory — which made two of them false. Separately, "~71 entries" was reported from a directory link count rather than a file count. Neither was an invented number: each was an accurate figure attached to a claim it did not support.

A test can only exercise the range its fixture spans

Portfolio volatility was measured over the whole price file — an eleven-year mean — which left the crisis brake inert, because an eleven-year average cannot rise. Every unit test passed, both engines agreed to the last bit, and every fixture was shorter than the window that was wrong. It was caught by reading a real run's output and noticing a number that was impossible.

Once out-of-sample data has been used to fix something, it is spent

This is the rule the project has broken once and documented rather than hidden. The sequence was: measure, find a null, revise the engine in response, re-measure on the same window. The resulting +2.15% cannot be cited. Only data nobody has examined settles whether a change helped.

Repository hygiene

  • Stage explicit paths. Never git add -A — it once swept 77 lines of someone else's half-written work into an unrelated commit, cleanly and with exit code 0.
  • Never run the generators (build:python, generate:notebook) while someone else owns engine.py. They read like checks and write like builds.
  • Read git diff --cached --stat before every commit and abort on an unexpected file.

11. If you are picking this up cold

  1. Read knowledge/rulebook.md. It is the honest account of what every number rests on. Its "Open items" section is the real backlog.
  2. Run npm run dev and upload the bundled sample to see the output shape. Remember the sample's figures are invented.
  3. Run the backtest against the cached price file (~90 s) to reproduce the null yourself rather than trusting this document. It stops at 2023-01-01 by default, so the numbers will be close to but not identical with section 5; add --no-respect-holdout only if you need an exact match, and understand what that flag costs before you use it.
  4. Trust the report's own headings over this document. Each performance block now names the span it actually covers — first rebalance, last, and the count — and any block under two years carries a warning that its CAGR annualises too few months to read. That machinery post-dates this guide, so where the two disagree, the report is current and this is not.
  5. Do not tune thresholds to improve the IC. That is the trap this repository has already documented against itself. Measuring is fine; adopting on data already used is fitting.
